## Session 1 — From code to container
- MLOps vs DevOps vs DataOps; LLMOps: same concepts + hosting open models on corporate infra + different observability + different drift.
- Three diagnosis questions: can you reproduce any past experiment from the artifact store alone? how long from trained to serving and is it automated? who gets paged when the model silently degrades? (Her example: plate/car models trained on Cairo data, deployed in Hurghada — data drift.)
- Maturity L0 notebooks → L1 manual scripts → L2 ML pipeline + tracking + basic CI (target of sessions 1–2) → L3 CD for ML (auto retrain on trigger, registry, monitoring) → L4 zero-touch + auto-rollback («الكمال لله»). CT = continuous training.
- Favourite interview question: team with mixed frameworks, Jupyter only, data on laptops, predictions over WhatsApp → answer: env vars/config + secrets manager (Vault), ONNX, FastAPI, MLflow + DVC, Docker.
- Notebook anti-patterns: unpinned versions → pyproject + Docker; secrets in GitHub (bots crawl repos) → .env in .gitignore / Vault; hard-coded paths → env vars; no seed; magic numbers → config.
- Structure: `src/` with `__init__.py`, `tests/` exactly that name, `configs/`, `notebooks/` exploration only, Dockerfile, pyproject, README. «اخرجوا من النوت بوك شوية».
- `pyproject.toml` replaces requirements.txt; optional deps (onnx) + dev deps (pytest) separate; `pip install -e .[dev]`. uv is 10–100× faster: `uv init`, `uv add`, `uv sync`; **commit `uv.lock`**.
- OOP: `ModelBase` ABC with `predict()` so swapping sklearn↔XGBoost leaves API unchanged; name classes after the business case (`RideDurationModel`), not the architecture; type hints; docstrings; composition.
- FastAPI checklist: Pydantic `Field(gt=0)` validation (passengers `ge=1, le=8` — "can't sit on someone's lap"); `/health` for LB/k8s probes; **load model once** (per request = 200–500 ms, «كارثة»); async handlers; response schema; auto docs `/docs`. 422 comes for free from Pydantic. `@field_validator`. "Never trust incoming data."
- Serialization table: JSON (readable, slow), MessagePack (binary, 15–30% smaller), Protobuf (smallest, gRPC), Pickle (Python-only, **insecure**, never in APIs), ONNX (graph + weights, portable).
- ONNX: train → export → optimize → run anywhere; ORT ~15 MB vs multi-GB torch images ("can't ship a 3 GB image"); `model.eval()`, dummy input fixes shape, `opset_version=17`, `dynamic_axes` for batch, `onnx.checker`. Use ONNX for C++/Java/edge, TensorRT/OpenVINO; skip if serving from Python and SLA already met. "Python = research and glue. C++/Rust/CUDA = production runtime."
- Docker: image = class, container = object; Dockerfile named exactly; registries (Docker Hub, Nexus); multi-stage `AS builder`; `ENV` names only; non-root user; layer-cache: copy pyproject + install deps before `src/`; Windows needs WSL2. docker-compose (API + MLflow, `:ro` model volume, `depends_on`).
- Logging: "print() is not logging" — structlog JSON with levels + correlation id (`request_id`), endpoint, `model_version`, `latency_ms`.
- pytest: `MagicMock` ("never call real ML code in unit tests"), parametrize, fixtures, `TestClient` for 200/422; coverage ≥80% is the CI gate, 90% core, <70% red flag: `pytest --cov=src --cov-fail-under=80`.

## Session 2 — Shipping to production
- MLflow vocabulary: Experiment (one per problem), Run, Artifact, Registry. "A registry is any place that stores things with versions" (like Docker Hub).
- `set_tracking_uri`, `set_experiment`; `start_run()` context manager; `log_params`, `log_metric` (repeatedly for curves), `log_model(registered_model_name=)`, `log_artifact`, `log_figure`, `set_tags` (model family, dataset version, stage, git commit). "Log everything (الأخضر واليابس)."
- UI: sort by metric, group, compare (parallel coordinates), run details (who, git branch/commit). System metrics: "GPU util 20% and training slow — why?" → data loader/CPU bottleneck.
- Registry: stages None → Staging → Production → Archived (slides) / **aliases** `champion`/`production` (transcript). "Serving code loads by stage/alias, never by number or path" — `models:/RideDurationModel/Production`.
- "Model zoo" should be classes/interfaces, not functions.
- MLflow vs W&B: MLflow self-hosted (governments, banks, on-prem); W&B SaaS with sweeps; "Learn MLflow deeply. Know W&B."
- DVC: Git can't hold data; `.dvc` pointer (md5 + size) in Git, bytes in remote (S3/GCS/local). Content-addressed: weekly +100 images → only new files stored. Commands: `dvc init` (needs git), `dvc add`, `dvc remote add -d`, `push/pull`, `status`, `checkout`, `diff`, `params diff`, `metrics show`, `dag`, `gc`. Workflow: `dvc add` → `git commit` + `git tag v1.0` → `dvc push`; switch: `git checkout v1.0` then `dvc checkout`. Pipelines `dvc.yaml` prepare→train→evaluate with `cmd/deps/params/outs`; `dvc repro` re-runs only changed stages; commit `dvc.yaml` + `dvc.lock`. Lineage: model v3.2 ← run_id 9a3f ← dvc tag rides-v2.1 ← git abc123f. "DVC has no real alternative."
- Code quality: Ruff (replaces flake8/isort/pylint), Black (or ruff-format), pre-commit with pinned `rev:`.
- Terraform (optional, advanced): provider/resource/state/plan-apply; never commit tfstate; S3 backend; `init fmt validate plan apply output destroy`.
- CI/CD: team lead with 20 devs can't review by hand → CI enforces standards (lint, type hints, tests, coverage ≥80%, build, push). Never push to main: branch → PR → CI → merge → tag. Triggers: push, `pull_request` with `paths`, `schedule`, `workflow_dispatch` ("your emergency lever"). `uses` vs `run`; matrix; `needs`; `docker/login-action` + `metadata-action` (short SHA + latest); environment secrets + approval gates; "Never echo a secret." Four ML triggers: push/PR, scheduled retrain, **drift signal** (`repository_dispatch: types: [drift-detected]`, e.g. PSI > 0.25), manual. Full flow: push → ruff/black → pytest --cov → docker build → push (SHA tag) → terraform apply → deploy.
- Integration tests: module-scoped fixture; `app.dependency_overrides[Model] = lambda: mock` ("you test the API, not the model"); parametrized 422 cases; `test_health`; contract test on response keys.
- **Final project remarks**: peer review required ("your colleague must have CI"); RAG teams → use RAGAS; log prompt version, chunking, embedding model in MLflow; "I want to see your creativity: how you version the knowledge base, the chunks, and their snapshots"; her own mistake: an embedding model that didn't understand Arabic (tokenization); her team kept no prompt history → use Langfuse/MLflow prompt registry (`register_prompt`, aliases Draft→Staging→Production).
- RAG versioning slide: `dvc add data/knowledge_base/`; `dvc repro chunk_docs` → `chunks.jsonl`; eval set of 50–100 Q/A/doc triples; "a new law is passed → dvc add → dvc repro rebuilds the index". Index = chunks + embedding model + params; vector DB snapshot `docs_v3` with atomic alias swap. "A different prompt is a different model."

## Session 3 — Orchestration, inference, serving, release (slides only)
- Airflow: "A cron job in a file is not a pipeline. A DAG is." Components: web server, scheduler, executor (Sequential/Local/Celery/K8s), worker, metadata DB. `DAG(schedule="@weekly", catchup=False, retries=2, retry_delay=5m)`. Tasks small + idempotent; heavy imports inside callables; `>>`; operators Python/Bash/BranchPython/Email; sensors File/ExternalTask/HttpSensor on `/health`. Evaluate task compares candidate vs Production.
- Inference patterns: "the most expensive ML mistake is deploying a good model the wrong way." REST API for nightly recommendations $800 vs $12 batch (66×); nightly batch for fraud → $2M slips; Kafka for weekly forecast → 3 months wasted. Rule: user waits → web service (<200 ms); can precompute → batch (Parquet + Airflow); react <1 s → streaming (Kafka/Redis Streams). Batch: load `models:/…/Production`, Parquet, stamp `run_date`. Streaming: broker-agnostic consumer, model loaded once. "If the stakeholder says nightly is fine — use batch."
- Serving: "Inference is a function call. Serving is everything around it." "A checkpoint is not a product. It's a file." "Training is a research problem. Serving is a systems problem." Vocabulary: p50/p95/p99 ("the average lies; p99 breaks your SLA"), throughput, batch size, GPU utilization (naive FastAPI 8–15%), cold start. Four-layer stack: L1 transport/API, L2 scheduling (batching, queue, versioning), L3 runtime, L4 hardware. Ownership: FastAPI L1; BentoML L1+L2; Triton L1–L3; KServe L1+L2+K8s; vLLM L1–L3 (LLM). Categories: CAT1 FastAPI ~10 rps; CAT2 BentoML ~200 rps ("start here, solves 90%"); CAT3 TensorRT+Triton ~2000; CAT4 ORT/OpenVINO CPU 2–8×; CAT5 vLLM. "Move right only with a measured reason (a Locust report)." FastAPI's four problems: batch size 1, GIL, eager runtime, no versioning/health (A100: 85 ms → 4,200 ms p95 at 100 users). BentoML fixes: `batchable=True`, Runner in separate process, `/healthz` `/readyz`, `bentoml containerize`. GPU levers: graph optimization, reduced precision (FP16/INT8, ~300 calibration samples), device concurrency. Managed vs self-hosted: MVP → managed; regulated → check compliance; high traffic → self-host; open-source LLM → vLLM self-hosted.
- Locust: max RPS, p50/p95/p99, first component to break, errors 0%. ML specifics: GIL, cold start, memory growth → OOM. LLM dims: **TTFT**, TBT (<50 ms/token), concurrency under continuous batching, context length (test at p95 context). `HttpUser`, `wait_time=between(0.5,2)`, `@task(weight=10)`, `catch_response`; headless `--csv` in CI, fail if p95 > threshold.
- Release: Blue/Green (instant switch, 2× cost, nginx upstream + reload); Canary 5→20→50→100% (nginx `weight=95/5`, advance only if p95 stable, MAE no worse, errors 0%); A/B (`md5(user_id) % 100`, log variant, business KPIs, ≥1000 per variant); Shadow (`asyncio.create_task`, zero added latency, log diff, double compute). Order: shadow → canary → A/B. "Canary is the right default." Netflix blue/green, Amazon canary auto-rollback 15 min, Booking A/B, Meta 48 h shadow.
- S3 project asks: Airflow DAG, BentoML micro-batching, Parquet batch scorer, Kafka/Redis consumer at 100 events/s, **vLLM serving Qwen2.5-7B-Instruct via OpenAI SDK with streaming, TTFT and throughput**, Locust 100 users, nginx canary 5/95 with rollback, one diagram with all three patterns sharing the registry.

## Session 4 — Monitoring, observability, LLM evaluation (slides only)
- "Software fails loudly. Models fail quietly." 91% of models lose accuracy over time; ~2 weeks before anyone notices.
- Drift: data P(X) (fraud model, 40% Saudi traffic), concept P(Y|X) (3 new-device logins → normal after UX change), prediction (churn 0.12→0.31, early warning), label (default rate 2%→7%). Root causes in order: upstream bug ("most drift is this": cents→dollars), seasonality (Ramadan, Black Friday — don't retrain), users changed (cohorts), training/serving skew. "Rule out a broken pipeline before you ever schedule a retrain."
- Tiers: watch now (latency, RPS, errors, schema, nulls), watch today (feature drift vs **frozen reference**, score histogram, positive rate), check later (labels). "The proxies are your alarm. The labels are your audit."
- Tests: KS (numeric), Chi-square (categorical), JS (bounded); Wasserstein, MMD, domain classifier for embeddings. Don't alert on p-values at scale — alert on the size of the shift.
- RAG drifts: embedding (index vs query encoder differ → zero-hit rate, mean top-1 sim, **assert encoder name at startup**), corpus (deleted docs still retrievable → doc age, index vs source count), retrieval (chunk-reuse concentration, context precision by week), query-intent (refusal rate, out-of-scope rate, weekly clustering). LLM drifts: provider (pin dated snapshot, golden set nightly), prompt ("a hundred small edits"), trajectory (steps per task, cost per task), evaluator (pin judge, temp 0).
- Stack: Prometheus (pull, `/metrics`, 15 s), Grafana, Evidently (this week vs training data), Langfuse (inside an LLM app), RAGAS (number on quality).
- Prometheus: counter (`rate()`), gauge, histogram; never unbounded labels (user_id, request_id); exporters node/cAdvisor/DCGM; vLLM/Triton built-in. Starter metrics: `ml_predictions_total{model,version,outcome}`, `ml_inference_latency_seconds{stage}` buckets `.01 .05 .1 .5 1`, `ml_prediction_score` histogram, `ml_inflight_requests`; `make_asgi_app()` at `/metrics`; `PROMETHEUS_MULTIPROC_DIR`. PromQL: `sum(rate(...[5m])) by (version)`, `histogram_quantile(0.95, sum(rate(bucket[5m])) by (le))`, `up{job=...}==0`.
- Grafana: 4 rows (service, resources, model behaviour, quality & drift), `$model` variable, deploy annotations ("half of drift investigations end when you see the spike land on a release"), **provision as code** ("a dashboard built by clicking dies with the pod"). Alerts `ModelTargetDown` (for 2m, page, runbook link), `NoPredictions`; **page on symptoms, warn on causes**; Alertmanager routes by severity.
- Evidently (pin 0.7.x): Report vs frozen reference, Tests for CI, one row per window/column/metric in PostgreSQL with model version. Four gates before retrain: sustained 2 days, not a bug, enough labels, 7-day cooldown + challenger beats champion.
- Metrics/logs/traces: "something changed" / "what exactly happened" / "where time went". "Never sample your prediction logs."
- Incidents: banking fraud (piastres vs pounds, found after 9 days), Baltimore cameras (per-device baseline), NYC MyCity RAG bot (illegal advice 5 months — **no golden eval set**; "a disclaimer is not a control, a feedback form is not a metric"), Instacart March 2020 (93%→61%), Zillow, Google Flu, Knight Capital ("97 warning emails were not alerts"), Air Canada chatbot ("you own what your model says" — faithfulness; "could you produce the trace?"). Her own: 4.93B tokens/month (~$49k) in non-prod, eval harness 22% → per-team token budgets; bilingual RAG zero-hit after nightly index rebuild with a new embedding model (18% of Arabic answers "not enough information") → store encoder name in index metadata, refuse to start on mismatch, alert zero-hit >5%, measure per language. "The model was never the root cause."
- Langfuse: trace (user_id, session_id, tags, release) → observations (span / generation with tokens+cost / event), session, score, dataset. `@observe(name=...)`, `langfuse.openai` wrapper (start here), callbacks, OTel. Name spans after the job (`retrieve`, `rerank`, `guardrail_in`); `flush()` in scripts; never trace secrets; mask PII. Metadata contract: user_id, session_id, release, prompt version, environment, tags (rag, arabic), metadata (k, index version, model). "Set session_id and user_id from the first trace." One conversation = one trace, turns as spans. Prompt management: `get_prompt("rag-system", label="production", cache_ttl_seconds=60)`, `compile`, `prompt.config`, `langfuse_prompt=` links trace to version; labels are movable pointers → **rollback is a label move, not a deploy**; fails open with cache. Promotion: edit → dataset run → CI faithfulness + cost → `canary` label 10% → compare → move `production`. Datasets: every bad answer, multi-hop, ambiguous, out-of-scope, no-answer, both languages, a few easy. "50 well-chosen items beat 5,000 scraped ones." Scores: programmatic (100%: valid JSON, zero chunks, citation present), LLM judge (1–5% live, 100% dataset), human. Cost per trace (alert > 2× 7-day baseline), input/output ratio, TTFT alert p95 > 2 s. Self-host: web, worker, Postgres, ClickHouse, Redis, S3/MinIO.
- RAGAS: sample = user_input, retrieved_contexts, response, reference. "It is a judge, not a measurement." "Absolute numbers lie, deltas do not." Faithfulness = supported claims / total (blames generator; a confidently wrong doc gives a faithful wrong answer); Response relevancy (questions regenerated from answer, cosine to real question; exclude refusals); Context precision (retrieval, reference-free vs answer); Context recall (needs reference, "the expensive one"); Factual correctness; Noise sensitivity. Start with faithfulness + relevancy + context precision. Precision/recall pair: low recall → smaller chunks / higher k / better embeddings; low precision → reranker / lower k; both high + low faithfulness → fix the prompt. Test set: mine production, `TestsetGenerator`, hand-written adversarial, review, **freeze and version**, balance by language/type; "a 60-question set you trust beats 2,000 you've never read." Judge: calibrate vs 50–100 human labels, <~80% agreement = "a random number generator with good grammar"; pin judge, temp 0; **Arabic: judges weaker at claim decomposition → report per language, never pool**. Where: CI gate (fail if faithfulness < 0.85), nightly on 1–5% sampled traces, per-item regression before prompt promotion. Six ways to fool yourself: absolute number, mean only, moving test set, ignoring refusals, pooling languages, uncalibrated judge.
- Interview Q topics (12), runbook "the model degraded" (00 is it the model? 01 data pipeline 02 **roll back first, investigate second** 03 localize 04 real quality 05 decide and write), "an alert without a runbook is noise". Anti-patterns: alert on everything, retrain without gate, high-cardinality labels, inputs-only, rolling baseline forward, average-only, shipping an LLM feature with no eval or no cost view. Appendix cases: two versions serving (`count(count by (version)(up)) > 1`), feedback loop erasing evidence (hold-out control), timezone bug, disk filling (`predict_linear`), tokenizer truncation on long Arabic docs (evaluate by length bucket), feedback widget silently broken ("monitor your monitoring", `rate(feedback_total[6h]) == 0`).
