## A. LLMOps / RAG / agents posts
- **P1 Provider, prompt, trajectory drift**: trajectory drift = agent that took 4 steps now takes 9 (same answer, more cost/latency); provider drift = model behind the same API name changed; prompt drift = «Rule هنا، Example هناك» until behaviour changed. «في ال LLM Applications، ال Code لوحده مش هو ال System» — system = model + prompt + context + tools + agent behaviour. Method: **Trace → Version → Evaluate → Monitor**; record model, prompt version, steps, tool calls.
- **P6 RAG / vector drift**: embedding drift (model changed, index built with old one), corpus drift (docs changed, index not updated), retrieval drift (less relevant chunks). «ال RAG ممكن جودته تقل من غير أي Error واضح» — monitor retrieval quality and data, not just latency.
- **P64 MLflow for LLMs and RAG**: problem `prompt_v1 … prompt_v2_final_2`. Track prompt version, embedding model, retriever + params, eval metrics. Faithfulness (grounded in context or LLM added its own?) and Context Recall (did retriever bring what the answer needs?). Flow Context → Retrieval → Generation → Evaluation. When a score improves you must say what changed: prompt, embeddings, **chunking**, retrieval strategy.
- **P59 Monitoring part 4**: system monitoring (CPU/GPU, memory, error rate, p50/p95/p99 with Prometheus/Grafana) vs model monitoring ("runs with no errors and still gives bad results"). Embedding drift critical for RAG (docs from 2023, users ask about 2024). Methods: KS, PSI, Chi-square, JS, Wasserstein; embeddings → cosine distributions, cluster shifts. Responses: CT once drift passes threshold, fallback models, alerting, re-index / swap embedding model. Tools: Evidently, Arize, WhyLabs, Fiddler; "Langfuse is the default for LLM trace-level observability."
- **P76 "AI agents are just software"**: LLM returns structured output; your code owns control flow, state, retries, stopping. **Context engineering > prompt engineering** (memory, RAG results, tool outputs, history, state). «أقل Context ممكن… لكن يكون هو الصح. مش أكبر Context».
- **P73** one general agent with skills beats many specialised agents; code is the universal interface. **P69** verification debt: people followed AI 92.7% when right, 79.8% when confidently wrong → Guide → Verify → Solve. **P71** specs-to-code, deep modules, TDD in small steps, ubiquitous language.
- **P58** keyword → fuzzy → semantic search at scale. **P4** "Redis for semantic caching" (cache similar-meaning questions to cut latency/cost). **P41** tokenization/BPE, tokens vs context window vs cost, «Token ID مش هو الـEmbedding». **P43/P22** GenAI foundations, build-an-LLM course (tokenizer handles Arabic + English).
- **P10/P11/P26** on-prem LLM infra (multi-GPU vLLM, routing, LoRA serving, load testing, GPU telemetry) and AgentOps (durable execution, MCP tool contracts, permissions, human-in-the-loop, eval + observability, retries/timeouts/circuit breakers, rollback). "The real jobs are in the layer under the model."

## Support deck 1 — GitHub Actions Mastery (cicd.pdf)
- CI vs Continuous Delivery (human approves) vs Continuous Deployment. Blocks: Workflow, Event, Job, Step, Action, Runner. Files in `.github/workflows/*.yml`.
- Templates: minimal `ci.yml`; triggers `push/pull_request: branches: [main]` + `paths` + `tags: ['v*.*.*']`; test job `actions/checkout@v4` → `setup-python@v5` → install → `pytest --junitxml`; `.pre-commit-config.yaml` with `astral-sh/ruff-pre-commit` (`ruff --fix`, `ruff-format`) + `pre-commit-hooks` (trailing-whitespace, end-of-file-fixer, check-yaml, check-merge-conflict); `pre_commit_check` job ("the hook is a convenience, the workflow is the guarantee"); `needs: [lint, test]`; matrix (`fail-fast`, `include/exclude`); `container: image: python:3.12-slim`; `upload/download-artifact@v4`; `actions/cache@v4` keyed on `hashFiles`; secrets `${{ secrets.X }}` masked; `permissions: {contents: read, pull-requests: write}`; `if:` with contexts; `environment: production` approval gate; branch protection "require status checks"; `schedule: cron '0 2 * * *'` (UTC); `workflow_dispatch` with inputs; `continue-on-error` only for experimental checks.
- Slide bugs: `if:` checks `refs/heads/dev` but says "main"; pinned versions old.

## Support deck 2 — DevOps Fundamentals: Docker, Kubernetes, CI/CD (docker.pdf)
- DevOps loop; VMs vs containers; CLI → dockerd → containerd → runc; namespaces (what it sees) vs cgroups (how much: `--cpus`, `--memory`, `--pids-limit`); layers read-only + writable layer; registry/repo/tag/digest — **`latest` is not the newest**, pin tags or digests; networks (bridge, user-defined → by name, host, none); volumes/bind/tmpfs.
- Commands: build/run/ps/logs/exec/rm/rmi/login/tag/push/pull/inspect; `network create`; `volume create`; compose `up -d/ps/logs/exec/build --no-cache/down -v`.
- Dockerfile template: `python:3.12-slim`, `WORKDIR /app`, copy requirements first, `--no-cache-dir`, `USER 1000`, `CMD`. Speed/size: `.dockerignore`, slim base, multi-stage, BuildKit cache mounts. Security: pinned trusted base, never root, no secrets in images, `trivy image --exit-code 1 --severity HIGH,CRITICAL`, `trivy config .`, `docker sbom`, `--read-only --cap-drop=ALL --security-opt no-new-privileges --memory --pids-limit`, secrets at runtime (Vault), never `--privileged`, never mount docker socket.
- Compose: `web` (build, ports, `DB_HOST: db`, `depends_on`) + `db` (`postgres:16`, named volume).
- Kubernetes basics: control plane (API server, scheduler, controller manager, etcd), nodes (kubelet, kube-proxy, runtime); `kubeadm` or `minikube start`; Pod, Deployment/ReplicaSet, Service (ClusterIP/NodePort/LoadBalancer), Ingress, Namespace, ConfigMap, Secret ("base64, not encrypted"), PV/PVC; deployment with `replicas: 3` and requests/limits; `kubectl scale`, HPA, rolling updates, `rollout undo`.
- CI: `docker/build-push-action@v6` with `tags: ${{ github.sha }}` (add `docker/login-action`); GitLab CI and Jenkinsfile comparison; "one working end-to-end pipeline beats memorizing every feature."

## Support deck 3 — FastAPI for AI/ML/MLOps engineers (fastapi.pdf)
- "A trained model is not a product." Use case: LLM/RAG app streaming tokens while backend retrieves and calls the model. FastAPI = Starlette/ASGI + Pydantic + OpenAPI; type hints are the contract. "An API is a remote function call." Path = which resource, Query = how, Body = what, Header = metadata. `Query(le=100)`; pass `x-request-id` downstream. Inference = POST. Status codes incl. **422** (validation) and **429** (rate limited).
- Validation `Field(gt=0, lt=120)`, nested models, enums; `response_model` both directions. Layout `app/{main, api/routes, schemas, models, services, repositories, core, dependencies, db}`; routes thin, services logic, repositories only talk to SQLAlchemy. DB: SQLAlchemy `Prediction` table (JSON features for retraining/audit), Alembic migrations, session per request via DI, pooling, commit/rollback in finally. DI: `get_db()`, `get_model()` loaded once, `dependency_overrides` in tests.
- Async: helps I/O (DB, HTTP, LLM, vector DB); **blocking `model.predict()` in `async def` freezes the loop** → `run_in_threadpool` or worker/queue; "async does NOT make CPU inference faster."
- Rate limiting: Redis `incr` + `expire` middleware → 429; algorithms fixed window, sliding window, token bucket, leaky bucket. Slide bugs: `HTTPException` inside middleware (return `JSONResponse(429)` instead); `expire` on every request (only when `count == 1`).
- Middleware: timing `X-Process-Time`, logging, CORS, security headers, request ids; `Depends()` for per-route logic. Auth: 401 who vs 403 what. Errors: 4xx detailed, 5xx logged not exposed; `@app.exception_handler(ModelInferenceError)` → 500 "Model unavailable". WebSocket `/ws/chat`; **SSE** `StreamingResponse(media_type="text/event-stream")` yielding `data: {token}\n\n` for LLM tokens.
- FastAPI in front of vLLM: auth, rate limit, validation, history/system prompts, **RAG retrieval and tool calls**, post-processing; call `http://vllm-server:8000/v1/chat/completions` with `httpx.AsyncClient(timeout=30.0)` + `raise_for_status()`; "Never call an external inference service without a timeout"; streaming via `client.stream(...)` + `aiter_lines()` forwarding `data:` lines over SSE.
- Reference Todo API (FastAPI + Postgres + SQLAlchemy + Alembic + Docker Compose; Create/Update/Response schemas, never expose ORM; 201/204/404). Production checklist: env config + secrets manager, liveness vs readiness, structured logs + request ids, Prometheus/Grafana, workers, timeouts/retries/graceful shutdown/pooling. Mistakes: everything in main.py, blocking in async, reload model per request, no validation, raw DB objects, no timeouts, **no rate limit on LLM endpoints**, hardcoded secrets, no /health or logging.

## Support deck 4 — Kubernetes Deployment Strategies (Kubernetes .pdf)
- Scenario `payments-api` v1→v2, namespace `production`, Service + NGINX Ingress. Safe release needs availability, limited blast radius, health checks, fast rollback, visibility, version per request. Deploying (replacing Pods) ≠ routing traffic (Service selector / Ingress). **Labels are the routing contract**: `app`, `version`, `track` (stable/canary, blue/green). Probes: liveness `/healthz` (restart?), readiness `/readyz` (traffic?), startup; alive ≠ ready.
- Deployment template: `replicas: 3`, probes with `initialDelaySeconds`, requests 100m/128Mi, limits 500m/256Mi. Checks: `kubectl get deploy/pods -l app=…`, `rollout status/history`, `get events --sort-by`, `logs deploy/… --tail=100`.
- Recreate (downtime, dev only); Rolling (`maxUnavailable: 0`, `maxSurge: 1`, `set image`, watch for ImagePullBackOff/CrashLoopBackOff, `rollout undo [--to-revision]`); Blue-green (two Deployments `track: blue/green`, patch Service selector, keep blue until verified, 2× cost); Canary (stable + canary Services, second Ingress with `nginx.ingress.kubernetes.io/canary: "true"`, `canary-weight: "5"` → 5→20→50→100, rollback weight 0 or delete Ingress); A/B (`canary-by-header: X-Release-Track`, value `v2`; cookie/user/region/tenant); Shadow (`mirror-target`, `mirror-request-body: "on"`, responses discarded; tests startup/compat/latency/errors/resources, not UX).
- Decision guide: default rolling; instant full rollback → blue-green; gradual exposure → canary; specific users → A/B; test without affecting users → shadow; versions can't coexist → recreate. "Pick the simplest strategy that meets your rollback and risk needs." Release checklist before/during/after.
