Phase 3 · code tour

Measure first, then let a decision model improve itقيس الأول، وبعدين خلّي موديل القرارات يحسّن

Phase 2 answers questions; Phase 3 tells us how well, in numbers we can compare. A fixed set of questions with known answers (the golden set) is run through the pipeline; free deterministic metrics and an LLM judge (RAGAS) score it; every run lands in MLflow with the exact config and data versions. Then the JEV-RAG idea is tested: does a decision model (Jev) or a local cross-encoder reranker beat plain retrieval? Concepts: Concepts 3 · evaluation and tracking, Concepts 2 · JEV-RAG.

المرحلة 2 بتجاوب على الأسئلة؛ والمرحلة 3 بتقولنا بتجاوب كويس قد إيه، بأرقام نقدر نقارنها. مجموعة ثابتة من الأسئلة إجاباتها معروفة (الـ golden set) بتعدي على الـ pipeline؛ ومقاييس محسوبة من غير أي موديل (ببلاش) وحَكَم LLM (‏RAGAS) بيدّوها درجات؛ وكل تشغيلة بتتسجل في MLflow بالإعدادات ونسخ الداتا بالظبط. وبعدين بنختبر فكرة JEV-RAG: هل موديل القرارات (Jev) أو reranker محلي (cross-encoder) أحسن من الـ retrieval العادي؟ المفاهيم في صفحة المفاهيم 3 (التقييم والتتبع) والمفاهيم 2 (JEV-RAG).

The predictions file is the hinge: the expensive part (calling the pipeline) runs once, and any number of scorers read the file afterwards. That is why a judge failure halfway did not cost us the pipeline run (see Problems).

2. eval/golden.py: the golden set2. eval/golden.py: الـ golden set

data/golden/golden_set.jsonl: 28 pairs, each asked once in Arabic and once in English (56 questions), so the two languages are compared on exactly the same questions. Every reference answer was written after reading the article text in articles.json, not from memory.

  • in_scope (21 pairs, all four books) and explicit_ref ("What does Article 1 say…"): answerable; gold_articles are the articles a correct answer must cite.
  • repealed (Articles 60, 400): a correct answer says "repealed".
  • off_topic (tax, criminal law) and injection ("ignore all previous instructions…"): the correct answer is the exact refusal sentence.

GoldenItem validates each line (language matches the question, unanswerable items carry the exact refusal); check_golden() finds duplicates, unmirrored pairs and, with the corpus, wrong or repealed article numbers. A typo in a gold article fails a test instead of silently lowering a metric.

data/golden/golden_set.jsonl: 28 زوج، كل سؤال مرة بالعربي ومرة بالإنجليزي (56 سؤال)، عشان نقارن اللغتين على نفس الأسئلة بالظبط. وكل إجابة مرجعية اتكتبت بعد ما قرينا نص المادة في articles.json، مش من الذاكرة.

  • in_scope (‏21 زوج من الكتب الأربعة) وexplicit_ref ("المادة 1 بتقول إيه…"): ليها إجابة؛ وgold_articles هي المواد اللي الإجابة الصح لازم تذكرها.
  • repealed (المادة 60 والمادة 400): الإجابة الصح تقول "اتلغت".
  • off_topic (ضرايب، قانون جنائي) وinjection ("تجاهل كل التعليمات…"): الإجابة الصح هي جملة الرفض بالظبط.

GoldenItem بيراجع كل سطر (اللغة مطابقة للسؤال، والأسئلة اللي ملهاش إجابة معاها جملة الرفض بالظبط)؛ وcheck_golden() بتلاقي التكرار، والأزواج المش متطابقة، ومع الـ corpus بتلاقي أرقام مواد غلط أو ملغية. غلطة في رقم مادة بتفشّل test بدل ما تنزّل رقم من غير ما حد ياخد باله.

4. eval/ragas_run.py: the LLM judge4. eval/ragas_run.py: الحَكَم الـ LLM

RAGAS asks a judge model four questions, each blaming a different stage: faithfulness (is every claim supported by the articles? generation), answer relevancy (does it address the question? generation), context precision (are relevant articles ranked high? rerank), context recall (do the articles cover the reference answer? retrieval). Faithfulness and relevancy are skipped for refusals (no claims to check).

Choices: the current RAGAS 0.4 API (ragas.metrics.collections, async ascore); the judge comes from a different family than the generator when possible (models favour their own style: self-preference bias); a failing judge call is recorded on the row and counted (ragas_errors) instead of killing the run.

RAGAS بيسأل موديل حَكَم أربع أسئلة، كل واحد بيلوم مرحلة مختلفة: faithfulness (كل كلام في الإجابة موجود في المواد؟ الكتابة)، answer relevancy (بتجاوب على السؤال؟ الكتابة)، context precision (المواد المهمة جت في الأول؟ الـ rerank)، context recall (المواد بتغطي الإجابة المرجعية؟ الـ retrieval). والـ faithfulness والـ relevancy مش بيتحسبوا للرفض (مفيش كلام نراجعه).

الاختيارات: API الـ RAGAS 0.4 الحالي (ragas.metrics.collections وascore)؛ والحَكَم من عيلة مختلفة عن الموديل اللي بيكتب لما ينفع (الموديلات بتحب أسلوبها: self-preference bias)؛ ونداء الحَكَم اللي يفشل بيتسجل على السطر ويتعد (ragas_errors) بدل ما يوقّع التشغيلة كلها.

5. eval/judge.py: can we trust the judge?5. eval/judge.py: نقدر نثق في الحَكَم؟

A judge is a model too, so it is measured like one. sheet writes data/golden/to_label.csv (20 answered questions, 10 AR + 10 EN, opens in Excel with Arabic intact); a human marks each answer 1 (all legal claims supported) or 0. calibrate then reports:

  • agreement and Cohen's kappa of our judge with the human (kappa corrects for chance: 0 = chance, 1 = perfect);
  • the same for "RAGAS faithfulness ≥ 0.8";
  • self-preference probe: the same judge prompt run by the generator's own model;
  • verbosity probe: append a harmless sentence to every answer; a fair judge does not flip its verdict.

Position bias (swapping answers A/B) only applies to pairwise judges, so it is not probed here.

الحَكَم برضه موديل، فبيتقاس زي أي موديل. sheet بتكتب data/golden/to_label.csv (‏20 سؤال اتجاوبوا، 10 عربي و10 إنجليزي، وبيفتح في Excel والعربي سليم)؛ وإنسان بيحط لكل إجابة 1 (كل الكلام القانوني موجود في المواد) أو 0. وبعدين calibrate بتطلّع:

  • الاتفاق وCohen's kappa بين الحَكَم بتاعنا والإنسان (الـ kappa بتشيل أثر الصدفة: 0 = صدفة، 1 = تطابق كامل)؛
  • ونفس الحاجة لـ "RAGAS faithfulness ≥ 0.8"؛
  • اختبار التحيز للنفس: نفس prompt الحَكَم بموديل الكتابة نفسه؛
  • اختبار الإطالة: نزوّد جملة ملهاش ضرر على كل إجابة؛ والحَكَم العادل ميغيّرش حكمه.

تحيز الترتيب (لما نبدّل الإجابة A وB) بيخص الحَكَم اللي بيقارن اتنين بس، فمش بنختبره هنا.

7. eval/run.py: one command per experiment7. eval/run.py: أمر واحد لكل تجربة

uv run python -m legalrag.eval.run --name ret-hybrid-local --decider local --retrieval-only --mlflow
uv run python -m legalrag.eval.run --name baseline --ragas --mlflow
uv run python -m legalrag.eval.run --name baseline --ragas --from-predictions reports/eval/baseline/predictions.jsonl

Flags override settings for one run (--decider, --mode hybrid|dense|sparse, --context-size, --top-n, --gate). --retrieval-only stops before the LLM: ranking and gate metrics for free. rag_config() is the list of everything that changes an answer; it becomes the MLflow params and, for the winner, the registered config.

الـ flags بتغيّر الإعدادات لتشغيلة واحدة (--decider و--mode و--context-size و--top-n و--gate). و--retrieval-only بيقف قبل الـ LLM: مقاييس الترتيب والـ gate ببلاش. وrag_config() هي قايمة كل حاجة بتغيّر الإجابة؛ وبتبقى الـ params في MLflow، وللفايز بتبقى الـ config المتسجلة.

8. eval/track.py and the MLflow server8. eval/track.py وسيرفر MLflow

  • Server (compose profile tracking): runs and metrics in Postgres, artifacts in MinIO; the server proxies artifacts, so clients only need MLFLOW_TRACKING_URI. --allowed-hosts is required: MLflow rejects unknown Host headers.
  • log_eval_run(): params = rag_config; metrics flattened as all.mrr, ar.hit_at_5…; tags = git SHA, articles_md5, Qdrant collection, golden-set md5, eval mode. That is the lineage chain git SHA → DVC data → MLflow run.
  • register_config() / load_config(): the winning config is a tiny pyfunc "model" holding rag_config.json; promoting = moving the alias production; loading = models:/legal-rag-config@production ("load by alias, never by path").
  • السيرفر (profile اسمه tracking): التشغيلات والأرقام في Postgres، والملفات في MinIO؛ والسيرفر بيوصّل الملفات بنفسه، فالـ client محتاج MLFLOW_TRACKING_URI بس. و--allowed-hosts لازم: MLflow بيرفض أي Host header مش معروف.
  • log_eval_run(): الـ params هي rag_config؛ والأرقام بأسماء زي all.mrr وar.hit_at_5؛ والـ tags هي git SHA وarticles_md5 والـ collection والـ md5 بتاع الـ golden set ونوع التقييم. ودي سلسلة الـ lineage: git SHA ← داتا DVC ← تشغيلة MLflow.
  • register_config() وload_config(): الـ config الفايزة "موديل" pyfunc صغير جواه rag_config.json؛ والترقية = ننقل الـ alias اللي اسمه production؛ والتحميل = models:/legal-rag-config@production ("حمّل بالـ alias، عمرك ما تحمّل بالمسار").

  • Hybrid was not better than dense here. The keyword (sparse) signal is weak on its own (worst in English), and RRF gives it the same weight, so on "What is X?" it lifts a neighbouring article above the defining one (936 above 935, 803 above 802). A textbook default lost to measurement.
  • Jev reranks perfectly on this set, in both languages, for ~$0.0001 and ~0.5 s per question. The local cross-encoder is free per call but ~60× slower on this CPU and ranks worse.
  • The gate: off-topic/injection questions score ≤ 0.04 with Jev and every answerable one ≥ 0.79, so any threshold from 0.1 to 0.755 is perfect; we chose 0.5, the middle of the gap. With the local model the safe window is only 0.05–0.20, and the article's 0.755 would wrongly refuse 10%: a threshold belongs to one model.
  • Arabic questions vs English articles: on the 25 answerable mirrored pairs Jev picks the same top article in both languages, and the gate agrees on 28/28 pairs, so no query translation is needed.
  • البحث الهجين مكانش أحسن من الـ dense هنا. إشارة الكلمات (sparse) ضعيفة لوحدها (وأضعف في الإنجليزي)، والـ RRF بيديها نفس الوزن، فمع أسئلة "إيه هو كذا؟" بيطلّع مادة جارة فوق المادة اللي بتعرّف (936 فوق 935، و803 فوق 802). اختيار "الكتاب بيقول كده" خسر قدام القياس.
  • Jev رتّب صح 100% على المجموعة دي باللغتين، بحوالي $0.0001 ونص ثانية للسؤال. والـ cross-encoder المحلي ببلاش في النداء بس أبطأ حوالي 60 مرة على الـ CPU ده وترتيبه أضعف.
  • الـ gate: الأسئلة اللي بره الموضوع والـ injection درجتها ≤ 0.04 مع Jev، وكل سؤال ليه إجابة ≥ 0.79، فأي threshold من 0.1 لـ 0.755 بيشتغل صح؛ واخترنا 0.5، نص المسافة. ومع الموديل المحلي المسافة الآمنة 0.05–0.20 بس، والـ 0.755 بتاعة المقال كانت هترفض 10% غلط: الـ threshold بتاع موديل واحد بس.
  • سؤال عربي قصاد مواد إنجليزي: في الـ 25 زوج اللي ليهم إجابة Jev اختار نفس المادة في الأول باللغتين، والـ gate اتفق في 28 من 28، فمش محتاجين نترجم السؤال.

10. Problems we hit10. مشاكل قابلناها

  • "jev-router" is not Jev decisions: the only Jev id OpenRouter lists by default, typesafe/jev-router, is a router that picks which chat model answers. The decision model is called with the TypeSafe body at /api/v1/systemone. A one-call probe confirmed the format before any code was written.
  • Dependency chain: RAGAS 0.4.3 fails to import with the newest langchain-community (pinned to 0.4.1), and RAGAS → instructor → jiter<0.15 holds openai at 3.3.0 for the whole lock, the API included. Our code only uses long-stable OpenAI features; the chain is recorded so it can be lifted when instructor updates.
  • MLflow keeps global state: the active experiment id leaked between tests ("No experiment with id=1") and artifacts landed in ./mlruns of the repo. Each test now gets its own directory and experiment.
  • Out of credits mid-run: OpenRouter answered 402 during RAGAS judging; the account had no purchased credits, and free models are capped at 50 requests/day (one golden run is 56, with RAGAS ~600). The pipeline predictions were already saved, so nothing was lost; RAGAS errors are now recorded per row, and generation/judging can move to the Gemini API free tier (LLM_BACKEND=gemini, JUDGE_BACKEND=gemini).
  • Free tiers count requests per minute and per day: the first Gemini run crashed at question 16 ("limit: 15" per minute on Flash-Lite, and the client's two quick retries gave up long before the "retry in 32 s"). Fix: eval/pacing.py spaces request starts under the limit (zero 429s afterwards). The bigger judge model allowed only 5/min and 20/day; its daily cap ran out mid-run, so the judge moved to Flash-Lite. That makes generator and judge the same model, which is exactly the self-preference risk; the calibration against human labels is the safeguard, and the report says so.
  • Thinking models eat their own budget: Gemini 3.x Flash spends hidden reasoning tokens from max_tokens, so answers came back cut off until reasoning_effort: none; and the gate sweep first counted the run's own gate refusals at every threshold (fixed by recording who refused).
  • An emoji crashed a Windows console: MLflow prints "🏃 View run…", which the default cp1252 console cannot encode. Every CLI now switches stdout to UTF-8 in configure_logging().
  • "jev-router" مش هو قرارات Jev: الـ id الوحيد اللي OpenRouter بيعرضه افتراضيًا typesafe/jev-router ده router بيختار أنهي موديل chat يجاوب. موديل القرارات بيتنادى بـ body بتاع TypeSafe على /api/v1/systemone. ونداء تجربة واحد أكّد الشكل قبل ما نكتب أي كود.
  • سلسلة الاعتمادات: RAGAS 0.4.3 مش بيشتغل مع أحدث langchain-community (ثبّتناها على 0.4.1)، وRAGAS ← instructor ← jiter<0.15 مثبّتة openai على 3.3.0 في الـ lock كله، والـ API معاه. الكود بتاعنا بيستخدم مزايا قديمة وثابتة بس في OpenAI؛ والسلسلة متسجلة عشان نشيلها لما instructor يتحدث.
  • MLflow شايل حالة عامة: الـ experiment id النشط عدّى من test لـ test ("No experiment with id=1") والملفات اتكتبت في ./mlruns جوه الـ repo. دلوقتي كل test ليه فولدر وexperiment لوحده.
  • الرصيد خلص في نص التشغيلة: OpenRouter رد بـ 402 وقت حَكَم RAGAS؛ الحساب ملوش رصيد مشترى، والموديلات المجانية ليها 50 طلب في اليوم بس (تشغيلة golden واحدة 56، ومع RAGAS حوالي 600). الـ predictions كانت اتحفظت فمخسرناش حاجة؛ وأخطاء RAGAS بقت بتتسجل لكل سطر، والكتابة والحَكَم ممكن ينقلوا على الـ free tier بتاع Gemini API (LLM_BACKEND=gemini وJUDGE_BACKEND=gemini).
  • الـ free tier بيعد الطلبات في الدقيقة وفي اليوم: أول تشغيلة على Gemini وقفت عند السؤال 16 ("limit: 15" في الدقيقة على Flash-Lite، والـ client جرّب مرتين بسرعة واستسلم قبل "استنى 32 ثانية" بكتير). الحل: eval/pacing.py بيوزّع بداية الطلبات تحت الحد (ومفيش ولا 429 بعدها). والموديل الأكبر للحَكَم كان مسموح له 5 في الدقيقة و20 في اليوم بس؛ والحد اليومي خلص في نص التشغيلة، فالحَكَم نقل على Flash-Lite. يعني الموديل اللي بيكتب هو نفسه اللي بيحكم، وده بالظبط خطر التحيز للنفس؛ والمعايرة مع تقييم الإنسان هي الضمانة، والتقرير بيقول كده صراحة.
  • موديلات الـ thinking بتاكل ميزانيتها: Gemini 3.x Flash بيصرف tokens تفكير مخفية من max_tokens، فالإجابات رجعت مقطوعة لحد ما حطينا reasoning_effort: none؛ وكمان الـ gate sweep في الأول كان بيحسب رفض الـ gate بتاع التشغيلة نفسها في كل threshold (اتصلّح لما سجّلنا مين اللي رفض).
  • emoji وقّع الـ console بتاع ويندوز: MLflow بيطبع "🏃 View run…"، والـ console العادي (cp1252) مش بيعرف يكتبه. دلوقتي كل CLI بيحوّل الـ stdout لـ UTF-8 في configure_logging().
