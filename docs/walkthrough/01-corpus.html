2. settings.py2. settings.py

class Settings(BaseSettings) lists every setting with a type and a default: backends, model names, thresholds, URLs, data paths. pydantic-settings fills each field from the environment variable of the same name (case-insensitive) or from .env, and validates it, so a typo like GATE_THRESHOLD=1.7 stops the app at startup (Field(ge=0, le=1)).

  • Secrets (openrouter_api_key, typesafe_api_key, Langfuse keys) are SecretStr: printing settings shows stars; you call .get_secret_value() only where the key is used.
  • active_llm_base_url / active_llm_model are properties that pick OpenRouter or vLLM from llm_backend, so the rest of the code never repeats that if.
  • get_settings() is wrapped in @lru_cache: the environment is read once per process (the "load once" rule applied to config).

class Settings(BaseSettings) فيها كل إعداد بنوعه وقيمته الافتراضية: الـ backends، وأسماء الموديلات، والحدود، والـ URLs، ومسارات الداتا. pydantic-settings بيملا كل حقل من الـ environment variable اللي بنفس الاسم أو من .env، ويتأكد منه؛ فلو حد كتب GATE_THRESHOLD=1.7 التطبيق يقف وهو بيقوم (Field(ge=0, le=1)).

  • الأسرار (مفتاح OpenRouter ومفتاح TypeSafe ومفاتيح Langfuse) نوعها SecretStr: لو طبعت الإعدادات تظهر نجوم؛ وبتنادي .get_secret_value() بس في المكان اللي هيستخدم المفتاح.
  • active_llm_base_url وactive_llm_model properties بتختار OpenRouter أو vLLM حسب llm_backend، فباقي الكود مش بيكرر الـ if ده.
  • get_settings() عليها @lru_cache: الـ environment بيتقرا مرة واحدة في البروسيس (قاعدة "حمّل مرة واحدة" على الإعدادات).

3. logging_conf.py3. logging_conf.py

  • request_id_var is a ContextVar: a variable whose value is per request (per async task), so two users served at the same time never see each other's ID.
  • _add_request_id() is a structlog processor: a small function every log event passes through; it adds request_id.
  • configure_logging(level) chains the processors (merge context → add request id → level → ISO timestamp → exception info → JSON) and writes to stdout, where Docker and log shippers read.
  • get_logger(name) returns a logger; you call log.info("parsed", articles=1149) with key-value pairs instead of formatting strings.
  • request_id_var نوعه ContextVar: متغير قيمته خاصة بكل طلب (كل async task)، فلو مستخدمين اتخدموا في نفس الوقت محدش يشوف الـ ID بتاع التاني.
  • _add_request_id() عبارة عن processor في structlog: function صغيرة كل حدث log بيعدي عليها؛ وبتضيف request_id.
  • configure_logging(level) بتسلسل الـ processors (نجمع الـ context ← نضيف الـ request id ← المستوى ← الوقت ← تفاصيل الخطأ ← JSON) وبتكتب على stdout، المكان اللي Docker وأدوات جمع الـ logs بيقروا منه.
  • get_logger(name) بترجّع logger؛ وبتكتب log.info("parsed", articles=1149) بمفاتيح وقيم بدل ما تركّب جمل.

4. ingest/schema.py: the Article record4. ingest/schema.py: سجل المادة

A Pydantic model, so every record is typed and validated (article_number must be ≥ 1). Fields follow the handbook schema, extended with what the PDF needed:

  • hierarchy: book (الكتاب), chapter (الباب), section (الفصل), subsection (الفرع), topic (numbered headings), plus heading_en (the English path). Later these become search filters.
  • text: text_ar, text_en, kept exactly as written apart from extraction repairs.
  • status: is_repealed, note, quality_flags (documented source defects) and source_page.
  • identity: id (eg-civil-147), citation and citation_ar are derived from the number and checked on load, so they can never drift. extra="forbid" rejects unknown fields: a schema mismatch fails instead of passing silently.

Pydantic model، فكل سجل ليه أنواع ومتأكد منه (article_number لازم ≥ 1). الحقول ماشية على شكل الهاندبوك، وزودنا اللي الـ PDF احتاجه:

  • التسلسل: book (الكتاب)، chapter (الباب)، section (الفصل)، subsection (الفرع)، topic (العناوين المرقمة)، وheading_en (المسار بالإنجليزي). بعدين دول هيبقوا filters في البحث.
  • النص: text_ar وtext_en، زي ما هما مكتوبين بالظبط ماعدا تصليح أخطاء الاستخراج.
  • الحالة: is_repealed وnote وquality_flags (عيوب معروفة في المصدر) وsource_page.
  • الهوية: id (eg-civil-147) وcitation وcitation_ar بيتحسبوا من رقم المادة وبيتراجعوا وقت التحميل، فعمرهم ما يختلفوا عنه. وextra="forbid" بيرفض أي حقل غريب: لو الـ schema اختلفت البرنامج يفشل بدل ما يعدّي.

6. ingest/parse.py: the parser6. ingest/parse.py: الـ parser

The core idea. In this PDF an article runs from its Arabic header (مادة…) to the next Arabic header and contains, in order: Arabic text, English text, then the headings that belong to the next article. The parser walks the lines once and moves each article through four modes:

الفكرة الأساسية. في الـ PDF ده المادة بتبدأ من عنوانها العربي (مادة…) لحد العنوان العربي اللي بعده، وجواها بالترتيب: النص العربي، وبعده الإنجليزي، وبعدين العناوين اللي تخص المادة اللي جاية. الـ parser بيعدي على السطور مرة واحدة وبينقّل كل مادة بين أربع حالات:

ARABICcollect Arabic text
→
ENGLISHcollect English text
⇄
ARABIC_AGAINa later Arabic paragraph (AR1, EN1, AR2, EN2 layout)
→
NOTEa repeal note inside English text
→
HEADINGSlines for the next article
PieceWhat it does and whyبيعمل إيه وليه
START_MARKERThe code starts after نصوص القانون المدنى; the decree before it has its own "مادة ١, ٢" that must not become Articles 1 and 2.القانون بيبدأ بعد نصوص القانون المدنى؛ مرسوم الإصدار اللي قبله فيه "مادة ١ و٢" بتوعه، ومينفعش يتحسبوا المادة 1 و2.
AR_HEADER, COMBINED_HEADER, EN_HEADERRegexes for مادة٢١, مادة٣٨( Article 83 and Article 12 (also rticle 452, which lost its "A").Regex لـ مادة٢١ ومادة٣٨( Article 83 وArticle 12 (وكمان rticle 452 اللي حرف A بتاعها ضاع).

A cross-reference that starts a line (Article 444 . inside Article 450) breaks the order, so we keep the longest strictly increasing run of header numbers (patience sorting, O(n log n)).العناوين الحقيقية أرقامها بتزيد على طول المستند. أي إشارة لمادة تانية بتبدأ سطر (Article 444 . جوه المادة 450) بتكسر الترتيب، فبناخد أطول سلسلة أرقام بتزيد.

_split_mixed(), _english_tail()Split "Arabic … English" lines at the last Arabic letter or diacritic (tanween at a word end once broke this), keeping the full stop with the Arabic.بيقسموا سطر "عربي … إنجليزي" عند آخر حرف عربي أو تشكيل (التنوين في آخر الكلمة كان مبوّظ ده مرة)، والنقطة بتفضل مع العربي.
_looks_like_body()Arabic appearing after English: is it the next paragraph of this article, or a heading? Body if it starts with a paragraph marker, is ≥ 50 characters (headings are short, wrapped body lines are ~70), or ends with ./،. Lines like الفصل… or ١ -… are always headings.لو عربي ظهر بعد الإنجليزي: ده فقرة جاية من نفس المادة ولا عنوان؟ بيبقى نص لو بادئ بعلامة فقرة، أو طوله ≥ 50 حرف (العناوين قصيرة والسطور العادية حوالي 70)، أو بينتهي بـ . أو ،. وسطور زي الفصل… أو ١ -… دايمًا عناوين.

Arabic repeal notes and number-only fragments are ignored.بتحدّث الكتاب/الباب/الفصل/الموضوع الحالي بالعربي والإنجليزي. سطر الكلمة المفتاحية (الكتاب الثاني) بياخد السطر اللي بعده كعنوان ويمسح المستويات اللي تحته؛ وباقي السطور بتبقى الموضوع. وملاحظات الإلغاء العربي والأرقام اللي لوحدها بتتجاهل.

7. ingest/validate.py and params.yaml7. ingest/validate.py وparams.yaml

validate_articles() returns a ValidationReport (errors, warnings, metrics). Per article: both texts present, no mixed scripts, under the length caps, and an English/Arabic length ratio inside the measured band (0.9–2.8), which catches text that moved to the wrong article even when the counts look right. Corpus-wide: numbers 1–1149 each once, 8 pinned golden phrases present, each book starting at its known article, and no book or chapter reappearing later. A documented anomaly turns only its listed checks into warnings; a new defect on the same article still fails.

main() reads params.yaml, writes reports/corpus_metrics.json (shown by dvc metrics show) and exits with code 1 on any error, which stops dvc repro before a bad corpus can be embedded.

validate_articles() بترجّع ValidationReport (أخطاء وتحذيرات وأرقام). لكل مادة: النصين موجودين، مفيش لغات متلخبطة، تحت حدود الطول، ونسبة طول الإنجليزي للعربي جوه النطاق اللي قسناه (0.9–2.8)، ودي بتمسك نص راح لمادة غلط حتى لو الأعداد شكلها سليم. وعلى مستوى القانون كله: الأرقام من 1 لـ 1149 كل واحد مرة، و8 عبارات ذهبية موجودة، وكل كتاب بيبدأ عند مادته المعروفة، ومفيش كتاب أو باب بيرجع يظهر تاني. والعيب الموثق بيحوّل بس الفحوصات المكتوبة له لتحذيرات؛ وأي عيب جديد في نفس المادة برضه بيفشل.

main() بتقرا params.yaml، وتكتب reports/corpus_metrics.json (اللي بيظهر في dvc metrics show)، وتخرج بكود 1 مع أي خطأ، فـ dvc repro يقف قبل ما داتا بايظة توصل للـ embedding.

8. dvc.yaml, pointer files and MinIO8. dvc.yaml وفايلات الإشارة وMinIO

  • data/raw/egyptian_civil_code.pdf.dvc: the PDF's MD5 and size. Git versions this small file; the bytes go to the MinIO bucket dvc.
  • dvc.yaml: stage parse (deps: the PDF, the whole ingest package, settings, logging and uv.lock, so even a pypdf upgrade rebuilds; outs: articles.json and articles.meta.json) and stage validate (deps: articles.json, validate.py; params: corpus; metrics: corpus_metrics.json).
  • dvc.lock: written by dvc repro, the exact hash of every dep, param and output. Committing it is what makes a result reproducible.
  • Credentials live in .dvc/config.local (never committed); the shared .dvc/config only says url = s3://dvc and endpointurl = http://localhost:9000.

Lesson from this phase: a .gitignore rule that hid the whole data/raw/ folder made DVC skip the pointer file inside it, so the PDF was never pushed. Deleting the cache and running dvc pull exposed it. Test the restore, not just the backup.

  • data/raw/egyptian_civil_code.pdf.dvc: الـ MD5 والحجم بتاع الـ PDF. Git بيتابع الفايل الصغير ده؛ والداتا نفسها بتروح bucket اسمه dvc في MinIO.
  • dvc.yaml: مرحلة parse (بتعتمد على الـ PDF وكود الـ parser؛ وبتطلع articles.json) ومرحلة validate (بتعتمد على articles.json وvalidate.py؛ والـ params: corpus؛ والـ metrics: corpus_metrics.json).
  • dvc.lock: بيكتبه dvc repro، فيه الـ hash بالظبط لكل مدخل وparam ومخرج. لما تعمله commit النتيجة بتبقى قابلة للتكرار.
  • بيانات الدخول في .dvc/config.local (عمرها ما تتعمل commit)؛ و.dvc/config المشترك فيه بس url = s3://dvc وendpointurl = http://localhost:9000.

درس المرحلة دي: قاعدة في .gitignore كانت مخبية فولدر data/raw/ كله، فـ DVC عدّى فايل الإشارة اللي جواه والـ PDF عمره ما اترفع. لما مسحنا الـ cache وعملنا dvc pull المشكلة بانت. اختبر الاسترجاع، مش النسخ الاحتياطي بس.

10. How we got here, step by step10. وصلنا هنا إزاي، خطوة خطوة

  1. Look before coding. Extracted all pages and printed the first ones. Counted headers: 1,089 English, 1,087 Arabic; reversed Arabic digits matched in 1,078 cases.
  2. Write tests from what you saw. A synthetic page with every quirk seen so far. The tests failed (no module yet).
  3. Make them pass with the simplest design: one pass, Arabic header to Arabic header.
  4. Run on the real PDF and audit. 1,123 records: 55–80 missing, 9 articles with no English, body text leaking into topics.
  5. Read the raw text around each failure. Found headers inside Arabic text, glued AR+EN lines, a header missing its "A", a repeal note inside English text. Added a failing test for each, then fixed.
  6. Audit again. 1,149 records, but long Arabic sentences in topics. Measured: real headings are short. Added the body-vs-heading rule, then a tanween bug showed up and got its own test.
  7. Validate and spot-check. 0 errors, 1 known anomaly, 20 random articles read by eye.

Every fix started as a failing test. That is what stops an old bug from coming back silently.

  1. بص قبل ما تكتب كود. طلّعنا كل الصفحات وطبعنا أولها. عدّينا العناوين: 1,089 إنجليزي و1,087 عربي؛ والأرقام العربي المقلوبة طابقت في 1,078 حالة.
  2. اكتب tests من اللي شفته. صفحة مصطنعة فيها كل الغرايب اللي شفناها. الـ tests فشلت (لسه مفيش module).
  3. خليها تنجح بأبسط تصميم: لفة واحدة، من عنوان عربي لعنوان عربي.
  4. شغّل على الـ PDF الحقيقي وراجع. 1,123 سجل: المواد 55–80 ناقصة، و9 مواد من غير إنجليزي، ونص مواد داخل في المواضيع.
  5. اقرا النص الخام حوالين كل مشكلة. لقينا عناوين جوه النص العربي، وسطور عربي وإنجليزي لازقين، وعنوان ناقص حرف A، وملاحظة إلغاء جوه النص الإنجليزي. كتبنا test فاشل لكل واحدة، وبعدين صلحنا.
  6. راجع تاني. 1,149 سجل، بس فيه جمل عربي طويلة في المواضيع. قسنا: العناوين الحقيقية قصيرة. زودنا قاعدة نص ولا عنوان، وبعدها ظهرت مشكلة التنوين وخدت test لوحدها.
  7. راجع وخد عينة. 0 أخطاء، ومشكلة واحدة معروفة، و20 مادة عشوائية اتقرت بالعين.

كل تصليح بدأ بـ test فاشل. وده اللي بيمنع bug قديم يرجع في صمت.
